# Weekly swing trade screen

Schedule: Mondays 6:47 pm ET (`CRON_TZ=America/New_York 47 18 * * 1`)
Data: this repo's `data/weekly/latest/`, built by the "Weekly screen data" GitHub Action (Yahoo Finance; SEC EDGAR when reachable), with Alpha Vantage as the insider fallback
Rules version: v1 (see `rules.json`)

## Prompt

Refresh Cade's "Swing trade screener" dashboard: https://claude.ai/artifact/ULtzUMAxM2BaXZmpGbamzU (a Dashboard-type artifact). The numbers (universe, scores, gates, finalists, ATR stops, earnings, insider flags) are computed by code in Cade's GitHub repo CadeBrek/swing-screener; your job is the judgment half: news write-ups, the pick log, the learning log, publishing and the report. Do NOT use Bigdata.com (Cade is out of credits); use Alpha Vantage only for the insider fallback in STEP 2b. Use today's date in America/New_York as TODAY. Work in a scratch folder; write Python for all math (never compute numbers by hand). Never change the scoring rules (rules version v1; changes only come from the monthly review with Cade's approval, as a new rules version in the repo).

STEP 1 - Get this week's data. Call add_repo with owner CadeBrek, repo swing-screener (access push), then `git clone --depth 1 https://github.com/CadeBrek/swing-screener repo`. Read repo/data/weekly/latest/status.json.
- If status.run == TODAY and status.ok is true, continue.
- Otherwise the GitHub Action has not run yet (it is scheduled 4:45 pm ET, 5:45 pm in daylight time, and GitHub can run late). Trigger it: append one line with the current UTC time to repo/data/run-weekly, commit "Run weekly screen data" and push. Then wait (Bash run_in_background with an until-loop that does `git -C repo pull -q` every 30 seconds) up to 25 minutes for status.run == TODAY. If it never arrives, or arrives with ok false, read repo/data/logs-weekly.txt and status.errors, change nothing on the dashboard, message Cade what failed in two sentences, and stop.
- Note status.errors (e.g. ATR or earnings unavailable for a symbol) for the report.

STEP 2 - Files. From repo/data/weekly/latest/ take screen.json, sectors.json, features.json and prices_all.json as they are. regime.json: fill each row's "read" with a 2-6 word plain description of the value (status.regime_extra has SPY 1-month/1-year, VIX 1-month change and WTI year-to-date change to help); change nothing else. finalists.json: the code leaves thesis, catch and invalidation blank, sentiment null (Bigdata's news sentiment has no free source; analyst_rec is Yahoo's 1-5 analyst mean, 1 = strong buy).

STEP 2a - Macro. If repo/data/macro/latest.json exists and its date is within the last 7 days, read it (Treasury yields, 2s10s and 3m10y spreads, fed funds; CPI, unemployment and the high-yield spread when available) for one line in the report. It never changes the screen.

STEP 2b - Insider fallback. The SEC blocks GitHub's servers, so the code usually leaves insider_flag "Unavailable". For each finalist whose insider_flag is "Unavailable", call Alpha Vantage INSIDER_TRANSACTIONS (symbol, from_date = TODAY minus 90 days), ONE CALL AT A TIME at least 2 seconds apart (8 of the free key's 25 daily calls). Parse the rows with python (transcribe the relevant rows into a script if the result is inline; if it is saved to a file, read it from there). Use only transactions dated within the last 90 days.
  - Count ONLY open-market purchases: acquisitions coded P, or described as a purchase at market price, with a share price above 0. Ignore grants/awards (A), option exercises (M), shares withheld for taxes (F), gifts (G), and any row with a zero price.
  - insider_buys_90d = number of distinct insiders with an open-market purchase.
  - insider_flag (exactly one of these words): "Strong buy" = 2 or more distinct insiders bought, OR a CEO, CFO or President bought $100,000 or more in total. "Buy" = otherwise, at least 1 insider bought. "Caution" = no buys, and 3 or more distinct officers or directors made open-market sales (code S) totalling over $10,000,000, or a CEO/CFO sold more than 25% of their holdings where the data shows holdings after the trade. "Neutral" = everything else. "Unavailable" = the call failed, was rate-limited or returned nothing usable (including an empty list). Never guess, and never write "Neutral" when the data is missing.
  - insider_note = one plain sentence from the data: who bought or sold, dollar totals, and dates.
  - The insider read is information only. It does NOT change score, rank, status, entry zone or stop.

STEP 3 - News. For each finalist run one WebSearch for recent news ("<company name> stock" with the month and year), and WebFetch an article if the snippets are too thin. Write three short fields in plain English, paraphrased (never copy sentences), only from the data and articles you retrieved: thesis (why it screens, 1-2 sentences, cite the actual momentum numbers from the file), catch (main risk or reason to wait, 1-2 sentences; mention the insider_note if the flag is Strong buy, Buy or Caution), invalidation (a concrete price level from the file, such as the stop or the 50-day, or an event). Save the finished finalists.json.

STEP 4 - Pick log. Read the dashboard's datasets/picks_log document (ArtifactData get, collection "datasets", doc_id "picks_log") to find its current file url, then download that file with the Artifact tool (action read, url above, path = the 32-character id after /_blob/). For EVERY existing row, set price_now to that symbol's price from prices_all.json, spy_now = prices_all.SPY, and as_of = TODAY (if a symbol has no price, leave its row unchanged and mention it). Then append one row per new finalist: {run: TODAY, symbol, rank, status, insider_flag, price_at_pick: price, spy_at_pick: SPY price, price_now: price, spy_now: SPY price, as_of: TODAY}. Never delete old rows.

STEP 5 - Learning log (every week; this is how the screen learns whether its rules work).
- ArtifactData get on the dashboard: collection "agent", doc_id "history_engine". Write its "text" field to history.py and note its "rules_version". Never edit history.py.
- ArtifactData get collection "datasets", doc_id "history"; download its file (Artifact read, path = the blob id) and save it as screen_history.json.
- mkdir out, then run: python3 history.py --history screen_history.json --run TODAY --features repo/data/weekly/latest/features.json --finalists finalists.json --regime regime.json --prices repo/data/weekly/latest/prices_all.json --spy <prices_all.SPY> --rules-version <rules_version> --out-history out/screen_history.json --out-scorecard out/scorecard.json
- If it errors, fix only your input files and rerun once. If it still fails (or says the run already exists), skip this step, leave the old history and scorecard in place, and say so in the report. If out/screen_history.json is over 7 MB, mention that it needs splitting soon.

STEP 6 - Publish. Upload each of finalists.json, screen.json, regime.json, sectors.json, picks_log.json, out/screen_history.json and out/scorecard.json with the Artifact tool (action publish, url above, asset true, file_path, one file per call). Then make ONE ArtifactData batch call of "update" writes to collection "datasets", doc_ids finalists, screen, regime, sectors, picks_log, history, scorecard (leave out any whose file failed), each setting source {kind:"file", url:<the new /_blob/ url>, name:<file name>} and updated {at:<ISO time now>, by:"Claude (weekly screen)"}. Read each document first to get its version for if_version. Do NOT change files/index.html, dash/meta, agent/history_engine, or the page design. After the writes, delete the assets you replaced (the old /_blob/ ids of those datasets) with Artifact action delete, url above, path = asset id, but only if no dataset still points at them.

STEP 7 - Keep the record. Copy the finished finalists.json and regime.json into repo/data/weekly/TODAY/ (overwriting the code's versions there; leave latest/ alone), commit "Weekly screen TODAY: news write-ups" and push. If the push fails, say so in the report; the dashboard is already updated.

STEP 8 - Report. Send Cade a short message (SendUserMessage) with: the regime in one line (add the yield-curve read and fed funds from STEP 2a if available); the finalists with each one's status; which are actionable now; any finalist with a "Buy", "Strong buy" or "Caution" insider flag, in a few words each (or "no notable insider activity"; say so if insider data was unavailable); any finalist that dropped out since last week (an open idea to reconsider exiting), and any logged pick whose weekly close fell below its stop; the pick log's average return vs the S&P 500 so far; and one line from the scorecard: if the "Finalists" row has 30 or more checked at 4 weeks, give its average vs the S&P next to "Passed, not picked"; otherwise say how many weeks are logged and that it's too early to judge. Mention any status.errors in a few words. Under 180 words, plain prose. Note that this is a screen, not financial advice. If any step fails, finish what you can, leave the old data for the failed dataset in place, and say what failed.
